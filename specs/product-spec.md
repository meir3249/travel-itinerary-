\## Product Requirements Document (PRD): Rome Interactive Map MVP\### 1. Objective and ScopeDevelop a lightweight, mobile-first web application featuring an interactive map of Rome to display curated locations, categorized by points of interest such as history, parks, shopping, and dining. The primary goal is to provide a seamless, visual navigation tool that operates fluidly on iOS and Android devices without requiring app store installation.\### 2. Approved Technology Stack\* \*\*Core Languages:\*\* HTML5, CSS3, \*\*Vanilla JavaScript\*\*. Chosen for maximum execution speed, zero compilation steps, and immediate deployment capabilities.\* \*\*Mapping Library:\*\* Leaflet.js. Selected for its minimal footprint, native touch-gesture support (pinch-to-zoom, drag), and direct DOM manipulation efficiency.\* \*\*Map Tiles:\*\* OpenStreetMap (OSM). A free, open-source tile provider that eliminates the need for credit card registrations or API usage limits during the MVP phase.\* \*\*Hosting:\*\* GitHub Pages. Provides free static hosting with global CDN delivery, perfectly aligned with our serverless architecture.\* \*\*Data Storage:\*\* Local JSON file (`places.json`). Acts as a lightweight, static database containing location coordinates and metadata.\### 3. Architectural Decisions \& Exclusions\* \*\*Client-Side Rendering (CSR) Only:\*\* The application relies entirely on browser-side execution.\### 4. Core Features (MVP)\* \*\*Dynamic Markers:\*\* Color-coded pins utilizing `Leaflet.awesome-markers` to differentiate categories visually.\* \*\*Rich Popups:\*\* Tapping a marker displays the location name, rating, atmosphere, and specific operational notes like reservation requirements or dress codes.\* \*\*Direct Navigation:\*\* Every popup includes a deep link to Google Maps (`\[https://www.google.com/maps/dir/?api=1\&destination=lat,lng](https://www.google.com/maps/dir/?api=1\&destination=lat,lng)`) to launch native turn-by-turn directions.\* \*\*User Geolocation:\*\* Implementation of the browser's Geolocation API to display a blue dot indicating the user's current physical location relative to the saved pins.\* \*\*Auto-Fit Bounds:\*\* The map automatically calculates and adjusts its zoom level on initial load to ensure all mapped coordinates fit within the viewport.\* \*\*Category Filters:\*\* Floating UI toggle buttons to show or hide specific location types.\### 5. Data Schema DefinitionThe `places.json` structure must adhere to the following schema to ensure seamless map rendering and future scalability:\* \*\*`id`\*\* \*(string)\*: Unique identifier (e.g., `colosseum-01`).\* \*\*`title`\*\* \*(string)\*: Full location name, including original and translated names.\* \*\*`category`\*\* \*(string)\*: Primary classification for marker color coding (e.g., `Historical`, `Restaurant`).\* \*\*`coordinates`\*\* \*(object)\*: Contains `lat` and `lng` numeric values for Leaflet mapping.\* \*\*`rating`\*\* \*(number)\*: Review score (e.g., 4.8).\* \*\*`atmosphere`\*\* \*(string)\*: Brief description of the vibe or environment.\* \*\*`reservation`\*\* \*(string)\*: Booking requirements (e.g., `Walk-ins`, `Required`).\* \*\*`notes`\*\* \*(string)\*: Operational tips, rules, or warnings.\* \*\*`tags`\*\* \*(string array)\*: Closed list of keywords for advanced filtering.\* \*\*`gmapsUrl`\*\* \*(string)\*: Direct deep link to Google Maps for quick navigation.
